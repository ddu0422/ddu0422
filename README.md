# 이두호

비즈니스를 이해하고 사람들이 사용하는 제품을 만들어 매출로 연결하고 싶습니다.\
중요한 기술적 문제를 직접 해결하고 팀이 함께 성과를 내도록 이끄는 엔지니어로 성장하고 있습니다.

## 나의 제품 원칙

> 고객이 사용할 이유와 비용을 지불할 이유가 분명한 제품을 만든다.

| 원칙                  | 실천 기준                                                                  |
| ------------------- | ---------------------------------------------------------------------- |
| 고객이 비용을 지불할 이유를 찾는다 | 누구의 어떤 문제를 해결하는지 확인한다.<br>고객이 얻는 가치와 매출로 이어질 이유를 구체화한다.                |
| 제품 전체를 기준으로 판단한다    | 요청이 제품의 방향과 정책에 맞는지 검토한다.<br>기존 사용자 경험과 장기 운영에 미칠 영향을 고려해 개발 여부를 결정한다. |
| 핵심 가치를 빠르게 전달한다     | 고객이 원하는 일을 끝내는 데 필요한 흐름부터 만든다.<br>처음 써도 이해하기 쉽고 현장에서 편한지 확인한다.         |
| 사용과 매출까지 확인한다       | 고객이 사용하는지 다시 찾는지 구매하는지 확인한다.<br>매출과 운영 비용을 함께 살피고 기대와 다르면 가정을 다시 검토한다. |

## 나의 기술 개발 원칙

> 문제에 맞는 기술을 선택하고 실제로 해결됐는지 끝까지 확인한다.

| 원칙              | 실천 기준                                                        |
| --------------- | ------------------------------------------------------------ |
| 문제와 제약부터 확인한다   | 사용자의 불편과 비즈니스 영향을 파악한다.<br>일정과 비용을 고려해 보장할 조건을 정한다.          |
| 전체 흐름에서 원인을 찾는다 | 사용자 화면부터 API와 DB 및 인프라까지 따라간다.<br>문제가 발생한 위치와 원인을 확인하고 해결한다. |
| 선택한 이유를 설명한다    | 성능과 복잡도 및 운영 비용을 함께 살핀다.<br>선택의 이유와 감수한 비용을 기록한다.            |
| 직접 구현하고 검증한다    | 동작 원리와 실패 조건을 이해하고 변경 효과를 측정한다.<br>반복되는 실수는 테스트와 자동화로 줄인다.   |

## 나의 리더십 원칙

> 리더는 팔로워를 성장시키지만 팔로워 또한 리더를 성장시킨다.

| 원칙                     | 실천 기준                                                                    |
| ---------------------- | ------------------------------------------------------------------------ |
| 조직의 목표와 개인의 성장을 함께 살핀다 | 회사가 추구하는 방향과 팀의 우선순위를 명확히 공유한다.<br>팀의 성과를 만드는 과정에서 개인도 실력을 쌓을 수 있도록 돕는다. |
| 팀이 스스로 판단할 수 있게 한다     | 문제의 배경과 목적을 공유하고 함께 판단 기준을 세운다.<br>팀원이 문제를 정의하고 결정하며 실행할 수 있는 환경을 만든다.   |
| 결정의 맥락을 남긴다            | 무엇을 결정했는지와 함께 왜 그렇게 판단했는지 기록한다.<br>새로운 팀원도 맥락을 이해하고 같은 기준으로 논의할 수 있게 한다. |
| 반복되는 문제는 구조부터 살핀다      | 문제가 발생하면 업무 흐름과 역할 및 판단 기준을 점검한다.<br>팀이 경험에서 배우고 같은 문제를 줄일 수 있도록 개선한다.   |
